# Google Drive в Exel

Підключення потрібне лише для хмарного відкриття та збереження. Локальні файли працюють без Google-акаунта. Застосунок працює з файлами власного формату, розміщеними на Drive; він не редагує документи Google Sheets.

## Підготовка Google Cloud

1. Відкрий [Google Cloud Console](https://console.cloud.google.com/) у своєму браузері й вибери або створи проєкт для лабораторної.
2. У розділі API Library знайди **Google Drive API** й увімкни його для цього проєкту.
3. Відкрий **Google Auth Platform**. Заповни Branding: назва застосунку Exel, контактна пошта та необхідні дані проєкту.
4. У Audience вибери відповідну аудиторію. Для особистого Gmail зазвичай потрібен External. Якщо доступний режим Testing, додай власну пошту до Test users.
5. У Data Access додай scope `https://www.googleapis.com/auth/drive.file`, який запитує Exel.
6. У Clients створи OAuth client типу **Desktop app**. Завантаж його JSON і збережи локально поза вихідним кодом.

Назви пунктів консолі можуть змінюватися. Офіційні інструкції: [Desktop OAuth](https://developers.google.com/identity/protocols/oauth2/native-app), [налаштування доступу Drive](https://developers.google.com/workspace/drive/api/guides/api-specific-auth).

## Підключення в Exel

1. Натисни Drive → «Підключити Google Drive».
2. Вибери завантажений OAuth JSON. Він містить об’єкт `installed` та `client_id`. JSON із `web` належить іншому типу клієнта й не підходить.
3. У системному браузері вибери свій акаунт і переглянь запит доступу. Вхід і згоду виконує власник акаунта.
4. Після завершення повернися до Exel. Очікування callback триває до трьох хвилин.
5. Створи невелику таблицю та обери Drive → «Зберегти в Drive».
6. Для перевірки відкрий її через Drive → «Відкрити з Drive». Порівняй назву й формули.

**OAuth JSON і файл таблиці — різні файли.** Перший налаштовує вхід, другий містить навчальні дані. Не передавай пароль Google програмі чи помічнику.

## Які файли видно

Exel використовує обмежений доступ `drive.file` та власну мітку файлів. Список показує таблиці, створені через Exel у цьому OAuth-проєкті. Вручну завантажений через сайт Drive JSON не має цієї мітки й не з’явиться в списку. Його можна завантажити на комп’ютер і відкрити локально в Exel.

Перше хмарне збереження створює файл; наступне збереження того самого хмарного документа оновлює його за ID. Перехід до нового чи іншого документа змінює поточний контекст. Це не автосинхронізація: натискай «Зберегти в Drive» після потрібних змін.

## Сеанс і типові проблеми

Токени залишаються лише в пам’яті. Після перезапуску імпортуй OAuth JSON і ввійди повторно. У межах сеансу access token оновлюється через refresh token. «Вийти» очищає локальний сеанс; відкликання згоди виконується окремо у Google-акаунті.

| Проблема | Що перевірити |
| --- | --- |
| Потрібне поле installed | Створи OAuth client типу Desktop app |
| access_denied у браузері | Акаунт, налаштування аудиторії, test users або обмеження організації |
| HTTP 403 | Чи ввімкнено Drive API; чи цей OAuth-проєкт має доступ до файлу |
| Список порожній | Спочатку збережи таблицю через Exel у цьому сеансі/проєкті |
| Вхід не завершується | Чи відкрився браузер; чи завершено згоду; чи не минули три хвилини; чи доступний локальний callback 127.0.0.1 |
| HTTP 401 або сеанс завершено | Підключи акаунт повторно |
| Помилка мережі | Інтернет і доступ до Google OAuth та Drive API |

Callback слухає випадковий порт лише на IPv4 loopback. Реєстрації URL у HTTP.sys і запуску Exel від адміністратора не потрібно. У тестах перевірено локальне повернення OAuth, state, PKCE, оновлення токена й HTTP-запити через підставний транспорт. Справжній Google-вхід, згода й обмін з особистим Drive потребують окремої перевірки разом із власником акаунта.
